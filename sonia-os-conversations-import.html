Reconstituer la mémoire de nos conversations.

Charge ton fichier conversations.json. Le classement s'effectue dans ton navigateur : aucun historique n'est envoyé sur GitHub, vers Supabase, ni à un service d'IA par cette page. Tu peux examiner les conversations et créer un paquet d'import vérifiable, que nous pourrons ensuite analyser et intégrer dans une base privée.

Important : cet outil prépare l'import, il ne remplit pas encore la mémoire cloud. Les données de famille, santé, démarches, finances, enfants, clients ou identifiants sont signalées automatiquement quand c'est possible, mais le filtrage peut se tromper. Aucune de ces conversations n'est sélectionnée par défaut.

Si tu as une archive ZIP, extrais d'abord conversations.json sur ton ordinateur. Ne dépose jamais ce fichier brut dans ton dépôt GitHub Pages.

3. Préparer la mémoire de SONIA OS

Relire, corriger et valider

Cette synthèse n’est pas une mémoire validée automatiquement. Vérifie chaque affirmation, retire les informations sensibles et corrige le texte avant de le sauvegarder.

Ouvrir ma mémoire cloud ELOAH ↗

Le texte reste sur ton appareil tant que tu ne le copies ni ne l’enregistres ailleurs. Pour sauvegarder : copie-le, ouvre ELOAH, sélectionne l’univers, colle le texte puis utilise « Sauvegarder dans mon cloud » avec ta session fondatrice.

4. Export complémentaire

Conserver un paquet de sources à relire

Le fichier exporté conservera le titre, la date, l'univers proposé, les messages texte du fil principal et les identifiants de provenance. Ce n'est pas un résumé intelligent : c'est une sélection de sources à examiner avant de retenir les décisions et les faits.

L'export reste sur ton appareil. Ne transfère pas de données sensibles dans un site ou un dépôt public.

SONIA OS · Phase préparatoire, aucune écriture automatique. La mémoire cloud existante reste inchangée et la validation humaine est obligatoire avant toute synchronisation privée.
